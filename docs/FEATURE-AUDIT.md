# Financial Portfolio Manager — requirements audit

First audited 15 October 2026 (Asia/Seoul); table consolidated 16 October 2026 to include the later increments recorded in the change log below. Baseline: the user's original program description and later requests, checked against current source and fixture tests. This is an implementation audit, not a certification of trading performance or broker compatibility. No private credential file was inspected.

## Findings

The application has a working desktop, portfolio, review, execution and supervised-learning foundation. **Continuous self-improvement remains partial.** An evidence-versioned outcome ledger, structured lessons with a reviewed lifecycle, optional AI post-trade reflection, an offline replay illustration and forward lesson trials exist. Benchmarks, external-trade import, held-out validation of arbitrary lessons and measured improvement do not. Market-wide discovery and structured consensus/macro research are still missing.

“Implemented” below means present in code, with relevant automated checks where stated. “Partial” means a narrower capability exists than originally described. “Missing” means no working implementation was found. “Unverified” distinguishes external behavior from fixture behavior; a passing fixture test does not establish live brokerage execution.

## What “self-improvement” currently means

Evidence: `electron/outcome-ledger.cjs`, `electron/outcome-evaluation.cjs`, `electron/learning-memory.cjs`, `electron/reflection.cjs`, `electron/lesson-trials.cjs`, `src/paper-replay.mjs`, `src/LearningPanel.tsx`, `src/LessonTrials.tsx`. Details: [Learning pipeline](LEARNING-PIPELINE.md) and [Agent evidence](AGENT-EVIDENCE.md).

1. **Outcome ledger.** App-originated broker fills and paper fills become one outcome per order, with economic changes stored as durable versions and withdrawn evidence kept as Retracted. Decision and proposal links are saved before automatic submission.
2. **Evaluation.** A local, no-API pass classifies outcomes (entry, pending, gain, loss, cost drag, missing evidence, retracted) using after-fee results. Native currencies stay separate; it draws no causal, benchmark or holding-period conclusion.
3. **Lessons.** Structured candidates carry source evidence, scope and gaps. The user edits, approves for 1–365 days, renews, retires or reopens them; evidence changes invalidate approval. Up to five approved lessons for the same account and symbol (or paper provenance) enter later reviews.
4. **AI reflection (opt-in, off by default).** A durable queue sends normalized evidence and the original thesis to the selected model under a separate budget and returns structured observations, unknowns and a tentative hypothesis. Suggestions can be copied into a draft; approval stays explicit.
5. **Offline replay.** Charts compares buy-and-hold with a closing-loss-threshold rule on completed daily bars, in earlier and later halves. It is an illustration of one explicit rule.
6. **Forward lesson trials.** In Journal → Reviewed lessons, an eligible lesson can be turned into an explicit exit rule (exit below entry, or protect gains from a peak) with commission, sale levy, slippage and a 1–365 day deadline. From the first fresh quote, an unchanged buy-and-hold arm and a candidate arm are tracked from future prices only; exits execute on the next observed quote. Net return, maximum drawdown and costs are shown for both. Trials are isolated by account, stop when the lesson's evidence changes or it is retired, and never change approval or trading rules. Annual capital gains, FX, liquidity and whole-share constraints are excluded; prices are sampled only while the app is open.

This loop does not change model weights, rewrite risk policy or establish that performance improved.

Still missing from the requested learning loop:

- Import and linkage of externally placed trades; complete entry/exit tax lots and corporate actions.
- Forward horizons and benchmark comparisons for outcomes.
- Contradiction handling between lessons.
- Held-out validation of arbitrary natural-language lessons, persisted validation verdicts, and comparison against an unchanged strategy across many cases.
- Automatic lesson-to-policy promotion, kept behind an explicit opt-in boundary if added.
- A dashboard measuring whether approved changes improved out-of-sample behavior. No performance claim can currently be made.

## Recommended implementation order

1. **Learning validation:** aggregate trial and replay results across lessons, add benchmarks and horizons, and import external trades so outcomes cover the whole account.
2. **Market discovery and research:** searchable security master/watchlist, screened candidates, relevant disclosures/news, then licensed consensus and macro sources. Report unavailable coverage honestly.
3. **Unified charts and performance:** U.S. candles in Charts, broker-history reconciliation, settled-cash valuation, cash-flow-aware historical portfolio returns and tax/basis import.
4. **Release and operational hardening:** signed distribution/update strategy, broader failure/recovery and external mock-account validation. Continue regression testing every change.

The existing desktop/approval/credential boundaries should be kept while implementing these steps. This audit does not authorize real trades, paid reflection runs, changing user guidelines or enabling automation.

## Validation and remaining test limits

Run `npm run validate` for type checks → build → unit tests → Electron UI suite → portable packaging → isolated startup verification. Run `npm run test:ui` for the UI suite alone. See [testing guide](TESTING.md).

The suite covers fixture behavior. The user's successful balance refresh and displayed U.S. holding are useful integration evidence, but do not establish autonomous trade quality, all KIS permissions, mobile delivery, tax correctness for every product, live settlement reconciliation or profitable adaptation. Screenshot capture and layout geometry checks are not a trained visual-difference model. No walk-forward strategy evaluation across many instruments, model-output quality evaluation suite or broker production certification exists.
